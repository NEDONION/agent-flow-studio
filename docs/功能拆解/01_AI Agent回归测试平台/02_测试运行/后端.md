# 测试运行-后端文档

## 1. 服务职责
- 编排测试任务执行。
- 调用对话模型完成评分与判定。
- 记录运行日志并回写用例最新结果。

## 2. 执行架构
- 调度器：任务队列 + 并发控制。
- 执行器：单任务模型调用器（含重试/超时）。
- 日志器：写入 `run_logs` 与摘要统计。

## 3. 数据模型
`RunTask`
- `taskId`、`caseId`、`status`、`startedAt`、`endedAt`
- `attempts`、`latencyMs`、`requestId`

`RunResult`
- `score: number`
- `passed: boolean`（score >= 80）
- `reason: string`
- `modelRaw?: unknown`

## 4. IPC/接口定义
- `run:single({ caseId }) -> { taskId }`
- `run:batch({ caseIds, concurrency }) -> { batchTaskId }`
- `run:cancel({ taskId | batchTaskId })`
- Event `run:progress({ batchTaskId, total, done })`
- Event `run:result({ caseId, score, passed })`

## 5. 业务规则
- 判定阈值固定为 80（可配置项）。
- 默认重试 1 次（仅网络类错误）。
- 并发默认 3，上限 10。
- 失败日志必须包含可读错误原因。

## 6. 异常处理
- 超时：`code=MODEL_TIMEOUT`。
- 限流：`code=RATE_LIMIT`，支持指数退避。
- 未知错误：`code=UNKNOWN_ERROR`，落日志并带 requestId。

## 7. 安全与审计
- API Key 仅在 Main 进程读取，不透传 Renderer。
- 日志脱敏（去除 Authorization、用户隐私字段）。

## 8. 测试要点
- 批量 100 条任务下队列稳定。
- 取消任务后不再触发后续请求。
- 重试策略仅对可重试错误生效。
