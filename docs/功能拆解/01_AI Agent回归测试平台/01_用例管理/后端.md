# 用例管理-后端文档

## 1. 服务职责
- 管理测试用例的持久化数据。
- 提供增删改查、导入导出能力。
- 保证 ID 唯一性与数据结构完整性。

## 2. 后端形态
- 本地后端：Electron Main 进程处理 IPC 与文件系统读写。
- 可选远端后端：同步用例到云端（后续迭代）。

## 3. 数据模型
`TestCase`
- `id: string`
- `prompt: string`
- `description?: string`
- `status: "idle" | "done"`
- `lastScore?: number`
- `passRate?: number`
- `createdAt: string`
- `updatedAt: string`

存储建议：
- 主存：`localStorage`（Renderer）或 `app.getPath('userData')/cases.json`（Main）。
- 推荐：统一落在 Main，Renderer 通过 IPC 访问。

## 4. IPC/接口定义
- `case:list({ page, pageSize, keyword, status })`
- `case:create({ prompt, description })`
- `case:update({ id, prompt, description })`
- `case:delete({ ids: string[] })`
- `case:import({ mode: "replace" | "merge" })`
- `case:export({ ids?: string[] })`

## 5. 业务规则
- 新建时生成 `id` 与时间戳。
- 删除后相关运行日志保留（仅断开关联，不级联删除）。
- 导入支持两种模式：覆盖导入、合并导入（按 id 去重）。

## 6. 异常处理
- 文件不可读/不可写：返回 `code=IO_ERROR`。
- JSON 反序列化失败：返回 `code=INVALID_JSON`。
- 记录不存在：返回 `code=NOT_FOUND`。

## 7. 安全要求
- Preload 仅暴露白名单 IPC。
- 过滤路径穿越与非法扩展名文件。
- 导出前剔除潜在敏感字段（如调试 token）。

## 8. 测试要点
- 合并导入去重逻辑正确。
- 大批量删除（>=500）稳定。
- 异常退出后数据文件可恢复读取。
