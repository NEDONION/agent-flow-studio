# agent-flow-studio PRD（桌面端）

> 文档日期：2026-04-18
> 说明：本项目仅面向桌面端，不做 Web 端。

## 一、项目基础信息

### 1.1 项目名称
- 项目名：**agent-flow-studio**

### 1.2 项目定位
agent-flow-studio 是一个基于 TypeScript + Next.js + Semi Design + Electron 的桌面端 AI 工作台 Demo。

目标是将 3 个核心 AI 场景整合到一个应用中：
- AI Agent 回归测试
- LLMOps 监控巡检
- RLHF 标注

项目不依赖数据库，采用本地存储（localStorage + 本地文件）实现数据持久化，适用于面试演示和个人技术作品展示。

### 1.3 核心目标
1. 整合 3 个 AI 子系统，支持单应用内快速切换与演示。
2. 基于 Semi 组件库构建统一、专业、可交互的桌面端界面。
3. 打通对话模型、VLM 模型、生图模型 API，形成“测试-监控-标注”闭环。
4. 保持 TypeScript 工程化与可扩展性，便于后续功能扩展。

### 1.4 技术栈要求
- 前端框架：Next.js 15 + TypeScript
- 桌面容器：Electron
- UI 组件库：Semi Design
- 图表：Recharts（或 Semi Chart）
- 网络请求：Axios
- AI 调用层：Vercel AI SDK（可选）
- 打包工具：Electron-builder
- 数据存储：localStorage + 内存 + 本地文件（可选）

### 1.5 桌面端可行性说明
1. Electron 支持 TypeScript，可复用现有前端代码。
2. 以 Electron 包裹现有页面，开发成本低，落地快。
3. 三大业务能力可完整复用，同时可扩展桌面端原生能力（托盘、通知、文件导入导出等）。
4. 可通过 Electron-builder 输出 Windows/Mac/Linux 安装包。

## 三、核心功能模块（Tab 切换）

全局交互约束：
- 顶部 Tabs 切换三大模块
- 模块内部逻辑独立
- 统一使用 Semi 设计风格
- 适配桌面端窗口缩放与常见分辨率

### 3.1 模块一：AI Agent 回归测试平台

#### 3.1.1 功能描述
实现测试用例管理、批量运行、结果校验与通过率统计。数据存储于 localStorage，支持本地 JSON 导入导出。

#### 3.1.2 核心功能
1. 用例管理
- 新增用例：输入 Prompt（可选描述）后保存。
- 编辑用例：更新 Prompt 与描述。
- 删除用例：支持单删与批量删除。
- 列表展示：ID、Prompt、状态、得分、通过率。
- 本地导入导出：支持 `.json` 文件。

2. 测试运行
- 单例运行：调用对话模型并返回得分（0-100）。
- 通过规则：得分 >= 80 视为通过。
- 批量运行：显示进度并回填结果。
- 日志记录：时间、耗时、得分、详情。
- 日志导出：导出为本地文本文件。

3. 结果统计
- 整体通过率（Progress）。
- 得分分布（柱状图）。
- 失败用例分析（得分 < 80）。

#### 3.1.3 Semi 组件要求
- Table、Input、Button、Modal、Progress、Chart/Recharts、Message、Input.Search

### 3.2 模块二：LLMOps 监控巡检控制台

#### 3.2.1 功能描述
模拟线上巡检，完成事实性、安全性和质量检查。日志以内存存储（重启后可重置），支持巡检内容导入与结果导出。

#### 3.2.2 核心功能
1. 对话质量巡检
- 输入单轮/多轮对话。
- 支持导入 `.txt` / `.md`。
- 调用模型执行巡检。
- 输出得分、事实性、安全性、优化建议。
- 结果标签：通过/风险/待优化。

2. 模型调用日志
- 列表展示时间、类型、耗时、得分。
- 支持展开查看详情。
- 支持清空日志。

3. 核心指标可视化
- 成功率（得分 >= 80）
- 平均调用延迟
- 平均得分
- 最近 10 次趋势图（得分、延迟）

#### 3.2.3 Semi 组件要求
- Input.TextArea、Card、Tag、Table、Chart(Line)、Button、Message

### 3.3 模块三：RLHF 标注平台（VLM + 生图）

#### 3.3.1 功能描述
实现“生成-解析-标注-反馈”闭环。支持图片生成、VLM 解析、评分标注与历史记录管理。

#### 3.3.2 核心功能
1. 生图功能
- 触发生图 API 生成图片。
- 支持默认提示词与自定义提示词。
- 支持预览、重生、保存。
- 记录生图日志（时间、提示词、地址）。

2. VLM 解析
- 对生成图或本地导入图片（`.jpg`/`.png`）做解析。
- 输出描述与关键元素。
- 支持“准确/不准确”反馈。

3. RLHF 标注
- 标注类型：生图质量、解析质量。
- 打分方式：Slider（0-10）。
- 可填写备注。
- 提交后保存到 localStorage。
- 支持历史查询、排序、筛选与详情查看。
- 支持标注记录导出 `.json`。

#### 3.3.3 Semi 组件要求
- Image、Button、Slider、Input.TextArea、Table、Modal、Message、Tag

## 四、全局通用功能（桌面端）

1. Tab 导航：顶部固定，当前模块高亮。
2. 窗口适配：支持窗口缩放与常见分辨率自适应。
3. 模型状态反馈：加载中（Spin）、成功/失败（Message）。
4. 数据持久化：
- 持久数据：localStorage / 本地文件。
- 临时数据：内存。
5. 全局样式：统一 Semi 主题、字体、间距、圆角。
6. 异常处理：API 失败、空输入、文件读写失败、窗口异常等。
7. 桌面端原生能力：
- 窗口控制：最小化、最大化、关闭。
- 托盘图标：打开/隐藏窗口、退出应用。
- 文件交互：导入导出文本、图片、JSON。
- 可选能力：开机自启、窗口置顶、快捷键。

- 所有关键操作有即时反馈。
- 模型调用过程可感知（加载态与结果态）。

- 三模块交互模式一致，学习成本低。
- 桌面端支持原生交互（拖拽、托盘、快捷键）。

## 八、注意事项

1. 不引入数据库，降低开发与演示复杂度。
2. API Key 不入库：通过 `.env.local` 与 Electron 安全配置管理。
3. Semi 组件优先，减少重复造轮子。
4. 演示前完成跨系统冒烟测试（窗口、托盘、导入导出、模型调用）。
5. 保持 TypeScript 类型定义完整，模块边界清晰，便于维护与讲解。
